How data flows

When you push code

  • 1You edit code on your Mac
  • 2git push sends it to GitHub
  • 3Vercel detects the push, builds the app, deploys it
  • 4Everyone on the live URL gets the new version

When a player taps "available"

  • 1Their phone writes to localStorage (instant, local)
  • 2Simultaneously writes to Firebase (shared database)
  • 3Firebase sends a real-time update to every other phone
  • 4Other phones update their localStorage and refresh the grid
Why both localStorage and Firebase? localStorage makes the app feel instant — no loading spinner when you tap. Firebase makes it shared. The app writes to both at the same time: local for speed, Firebase for everyone else.

src/components/

src/app/

  event/[id]/page.tsx — Single match detail
  manage/page.tsx — Admin: players, matches, divisions

Your daily workflow

# 2. Test locally

# 3. Push to GitHub

git push origin main

# 4. Vercel auto-deploys
# → live at cluichi.vercel.app in ~30 seconds
